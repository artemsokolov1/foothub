# Лендинг foothub.ru

Одностраничник FootHub: бонусы БК, переход в Telegram и MAX, короткие
футбольные 3D-игры (`/games`).

Vite + React + Tailwind 4 + Framer Motion + three.js (только на страницах
игр, подгружается лениво). Собирается в статику, поэтому подходит любой
хостинг: нужна только папка `dist`.

## Куда положить картинки

Два файла кладутся в `public/` **под этими именами**, иначе шапка их не
найдёт:

```
site/public/logo.png     логотип, квадратный, лучше 256×256 и больше
site/public/avatar.jpg   аватарка канала, тоже квадратная
```

`logo.png` используется трижды: в шапке, в подвале и как иконка вкладки.
Прозрачный фон приветствуется, но не обязателен — логотип лежит на скруглении.

## Запуск

```bash
cd site
npm install
npm run dev        # локально, откроется на http://localhost:5173
npm run build      # сборка в dist/
npm run preview    # посмотреть собранное перед заливкой
```

## Как поменять бонусы

Всё в `src/data/bookmakers.js`. Порядок в массиве = порядок на сайте.
Промокода нет — ставь `promo: null`, поле просто не нарисуется.

## Заметки по решениям

- **Наклон карточек на CSS, а не WebGL.** Страница должна открываться
  мгновенно с телефона в метро. Тяжёлая сцена ради подсветки того не стоит.
- **На тач-устройствах наклон выключен.** Курсора там нет, а «залипшее»
  наведение после тапа читается как поломка.
- **Логотипы БК не картинками, а плашками.** Своих файлов у нас нет, а чужие
  тянуть — это и вес, и вопрос прав. Имя на фирменном градиенте узнаётся не
  хуже и весит ноль.
- **Кнопки проминаются вниз при нажатии.** На телефоне палец закрывает
  кнопку, и подсветка при наведении не работает — нужен сдвиг.
- **Дисклеймер в рамке, а не серой строчкой.** Требование к таким сайтам, и
  прятать его нельзя.
- **`prefers-reduced-motion` уважается.** Кому анимации мешают, тот их не
  увидит.

## Деплой

После сборки это чистая статика: HTML, CSS, JS и картинки. Node на сервере
для показа сайта не нужен вовсе — он нужен только чтобы собрать.

### Что копировать на новую машину

Копируется **исходник**, а не сборка:

```
site/index.html
site/package.json
site/package-lock.json
site/vite.config.js
site/src/
site/public/           вместе с logo.png и avatar.jpg
```

`node_modules/` и `dist/` не копируются никогда. Первое весит сотни мегабайт
и собрано под конкретную систему — под Linux оно другое, чем под Windows.
Второе делается одной командой из первого.

Проще всего не копировать руками, а забрать репозиторий:

```bash
git clone <репозиторий> burmalda && cd burmalda/site
```

### Сборка на новой машине

```bash
sudo apt install -y nodejs npm     # или NodeSource, если нужен свежий Node
npm ci                             # ci, а не install: ставит ровно то, что в lock-файле
npm run build                      # получится dist/
```

`npm ci` вместо `npm install` здесь не придирка: он ставит версии строго по
`package-lock.json`, и собранный сайт получается тем же самым, а не «похожим».

### Показ

Отдавать нужно содержимое `dist/`. Любым веб-сервером, например nginx:

```
server {
    listen 80;
    server_name foothub.ru;
    root /var/www/foothub/dist;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
}
```

`npm run dev` на сервере запускать не надо — это режим разработки, он
медленный и небезопасный.

### Про домен и NAT

Целевой мини-компьютер стоит за NAT, и сайт на нём из интернета не откроется
без проброса портов или туннеля. Для лендинга это лишняя возня: он статический
и прекрасно живёт на любом обычном хостинге — туда заливается `dist/`, а на
домен ставится A-запись хостинга.

Мини-компьютер имеет смысл держать под конвейер, которому нужен круглосуточный
процесс, а не под страницу из трёх файлов.

## Выкладка на foothub.ru — GitHub Pages

Сайт статический, люди заходят на секунды. Отдельный сервер в России для
этого не нужен. Хостинг — **GitHub Pages**, бесплатно, HTTPS сам.

Живой репозиторий лендинга: [defffender/foothub](https://github.com/defffender/foothub).
Workflow в корне того репозитория (копия — `site/.github/workflows/pages.yml`).
Пуш в `main` собирает лендинг и выкладывает на GitHub Pages.

Пока DNS не переключён, сайт открывается по
https://defffender.github.io/foothub/ — но ассеты там могут не встать,
потому что сборка заточена под корень домена. Боевой адрес — https://foothub.ru/.

### DNS в reg.ru (один раз)

Корень `foothub.ru` — четыре A-записи GitHub Pages (старую `85.239.36.63` убрать):

```
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

По желанию IPv6 (AAAA):

```
2606:50c0:8000::153
2606:50c0:8001::153
2606:50c0:8002::153
2606:50c0:8003::153
```

`www` — CNAME на `defffender.github.io`.

Файл `public/CNAME` уже содержит `foothub.ru` и попадает в сборку.
После того как DNS дойдёт до GitHub, включится Let's Encrypt (Enforce HTTPS).

### Каждый раз: выложить

```bash
bash scripts/publish_site.sh
```

Через пару минут https://foothub.ru/ обновится сам.

### Про рекламу букмекеров

Сайт публичный и содержит партнёрские ссылки на БК. По российскому закону
интернет-реклама подлежит маркировке: нужен токен `erid` и пометка
«реклама» с указанием рекламодателя. Токен выдаёт оператор рекламных данных
(ОРД), обычно через партнёрскую программу — уточни у своих БК, выдают ли
они `erid` на креативы. Возрастная пометка 18+ и предупреждение на сайте
уже стоят, но маркировку они не заменяют.
